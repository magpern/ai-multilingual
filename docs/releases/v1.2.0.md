## What v1.2.0 adds

### Translation quality and safety

- **TQ.0** measurement harness and immutable official evidence pack `baseline-v1.1.0` (historical label retained)
- **TI.1** persist-path structural safety on sync and Jobs
- **TI.4** shared deterministic QA findings/policies with H1.1 additive scoring evidence

### Translation intelligence

- **TI.2** bounded translation context on the generation path
- **TI.3** exact approved TM direct reuse and relevance-gated assisted examples
- **TI.5** explainable read-only risk/readiness assessment (**R1.0**) — no score, no LLM confidence, no publication decision

### Background operations

- **TI.6** truthful provider usage and budgets, Retry-After handling, bounded concurrency, recovery/operator evidence improvements
- Exactly-once provider spend is **not** claimed (Outcome B may still re-call a provider after crash-after-Store)

### Controlled publication (TI.7)

- Durable third Store axis: `publish_status` / `published_at` / `published_by` (independent of `status` and `review_status`)
- Frontend publication gate (`Store::is_publicly_overlay_eligible()`)
- Single deterministic **PublicationPolicy P1.0** and single **PublicationService**
- Modes: `manual` (default), `approved_only`, `controlled_auto`
- Workspace / REST / CLI explain, status, publish, unpublish
- Sync and Jobs invoke the same publication service after successful translation persistence; publication failure does **not** fail the translation item or enter provider retry

## Why it matters

Operators can measure quality, block structurally unsafe persists, enrich generation with bounded context and approved TM, run deterministic QA and explainable assessments, harden Jobs at scale, and optionally gate frontend overlays behind an explicit publication state — without LLM confidence scores or silent upgrade auto-publish.

## Architecture highlights

```
measurement (TQ.0)
  → structural safety (TI.1)
  → bounded context (TI.2)
  → TM intelligence (TI.3)
  → deterministic QA (TI.4)
  → explainable assessment R1.0 (TI.5)
  → Jobs scale/safety (TI.6)
  → controlled publication P1.0 (TI.7)
```

`approved ≠ published`. Review workflow vocabulary (ADR-0015) is unchanged.

## Upgrade behavior (v1.1.0 → v1.2.0)

1. Install `ai-multilingual-1.2.0.zip` over the previous plugin directory.
2. Activate / visit wp-admin so `maybe_migrate()` runs.
3. Confirm `aiml_db_version` is **7**.
4. Confirm settings:
   - `segment_publication_gate_enabled` = **false** (default)
   - `auto_publication_mode` = **manual** (default)
5. Smoke-check previously visible translations remain visible with the gate OFF.

### Migration / backfill honesty

TARGET **6 → 7** adds publication columns. Existing rows that were publicly overlayable under the permissive pre-TI.7 path (non-empty translated text; status not `ignored` / `missing`) are backfilled to `publish_status = published`. Empty / ignored / missing rows are not promoted to public incorrectly. Migration is idempotent on re-run.

**This release must not hide existing public translations merely because the publication axis was introduced.**

### Safe defaults (critical)

**Upgrading does NOT start automatic publication.**

| Setting | Default |
|---|---|
| `segment_publication_gate_enabled` | `false` (gate OFF — legacy overlay semantics) |
| `auto_publication_mode` | `manual` |

New translations persist as `unpublished` until a manual publish or an explicitly enabled policy mode publishes them. Target content edits invalidate publication (`unpublished`). Source/staleness changes block **new** publication but do **not** automatically unpublish already-published rows. Automatic unpublish remains Deferred.

With gate **ON**, overlays require `publish_status = published` (plus existing render/staleness/language requirements). With gate **OFF**, pre-TI.7 overlay behavior is preserved; gate-off does **not** enable auto-publication.

### Controlled auto-publication honesty

`controlled_auto` requires structurally clean assessment, complete mandatory evidence, allowed provenance, public source, non-stale, non-rejected, and other frozen hard guards. Categories `blocked`, `needs_review`, and `review_recommended` **never** auto-publish. `structurally_clean` alone is insufficient. There is no force-publish bypass for hard blockers, no confidence score, and no LLM publication judge.

## Known limitations (current)

1. TM: Store `tm_id` dormant; no vector/fuzzy auto-reuse authority.
2. Deterministic QA: Deferred surfaces (units, wrong-language, SKU heuristic, never_translate, SEO length, …) per TI.4 matrix.
3. Assessment: no aggregate score (RA14 Deferred); Partial provenance facets.
4. Jobs: Outcome B may repeat provider spend after crash-after-Store; JO23 retention redesign and JO24 fairness Deferred; no site-wide daily spend platform; non-TM coalescing Deferred.
5. Publication: gate defaults OFF; mode defaults manual; AP12 Partial provenance; AP13–15 Deferred matrices; manual unpublish only (automatic Deferred); bulk/scheduled publication Deferred; no force-publish of hard blockers.
6. Platform carry-forwards from v1.1.0: translated leaf slugs Deferred; social images Deferred; SE10/SE11 Deferred; `blog_public=0` honesty; possible `/sv/` self-loop; possible dual product title from Rank Math/theme; Elementor body / nested identity limits; WP-CLI host quirks on some images.
