This release completes the **Translation Surface Coverage (TSC.0–TSC.6)** program on the v1.3.0 TIQ/OTL baseline and introduces formal **Extension API v1** for third-party registered meta, custom Gutenberg block adapters, visitor translation lookup, and source invalidation notification.

## What v1.4.0 adds

### Translation Surface Coverage (Complete)

- **TSC.0 — Internal Surface Capability Foundation** — reusable surface capability architecture, invalidation coordination, admitted surface ownership
- **TSC.1 — First-Class Taxonomy Terms** — native term identity, lazy hosted adoption, term editing/review/publication, visitor term overlays, Rank Math term coexistence
- **TSC.2 — Registered Meta Translation Surfaces** — exact-key registered meta, provider admission, Rank Math catalog ownership, post/term registered meta lifecycle
- **TSC.3 — WooCommerce Extended Translation Surfaces** — global Woo attribute labels, single-writer authority, shop-host rehome, variation safety, Woo email stale improvements
- **TSC.4 — Gutenberg Coverage Expansion** — broader supported Gutenberg field rendering, structural-attribute safety, block-field authority hardening, stale granularity
- **TSC.5 — Elementor Coverage Expansion** — authoritative `after_save` invalidation, shared structural safety, editor/preview context isolation, cache/language isolation, eight supported widget families hardened
- **TSC.6 — Public Extension / SEO Stabilization** — Extension API v1, public exact-key meta registration, public custom block adapter contract, `VisitorTranslationResolver`, `aiml_mark_source_dirty()`, WP-CLI extension diagnostics, Rank Math regression stabilization, ADR-0022

### Extension API v1 (new public contract)

- **`aiml_register_extensions`** — root extension registration phase with registry sealing
- **`ExtensionRegistrar` / `ExtensionManifest` / `RegisteredExtension`** — root ownership model
- **`ExtensionMetaDefinition`** — public exact-key meta registration (`provider_allowed` default deny)
- **`ExtensionBlockAdapter`** — narrow public custom block contract (Decision B)
- **`VisitorTranslationResolver`** — read-only visitor translation lookup with complete source identity + language code
- **`aiml_mark_source_dirty()`** — public invalidation helper (coalesced; shutdown sync authority)
- **WP-CLI:** `wp aiml extensions list`, `wp aiml extensions status <extension_id>`

See [docs/EXTENSION_API_V1.md](../EXTENSION_API_V1.md) and [ADR-0022](../adr/0022-public-extension-boundary-and-registration-lifecycle.md).

### Foundation retained from v1.3.0

- **TIQ Complete (TQ.0–TI.7)** — intelligence, QA, assessment, Jobs, controlled publication
- **OTL Complete (OTL.0–OTL.6)** — operator lifecycle presentation
- **Integration API v1** — unchanged `p:` plugin integration hook and contracts

## Why it matters

Sites gain broader site-neutral translation surface coverage (terms, registered meta, Woo extensions, Gutenberg, Elementor) with proven internal architecture, plus a bounded public Extension API for third-party plugins to register translatable meta and custom blocks without accessing internal Store or policy engines.

## Upgrade behavior (v1.3.0 → v1.4.0)

1. Install `ai-multilingual-1.4.0.zip` over the previous plugin directory.
2. Activate / visit wp-admin so `maybe_migrate()` runs.
3. Confirm `aiml_db_version` is still **7** (no new migration).
4. Confirm settings remain safe:
   - `segment_publication_gate_enabled` = **false** (default)
   - `auto_publication_mode` = **manual** (default)
5. Gutenberg and Elementor feature flags remain **OFF** by default unless already enabled.
6. Extension API registration is additive and code-driven; upgrading does **not** auto-register third-party meta or blocks.

**Upgrading does NOT start automatic publication, republish existing rows, or clear review state.**
