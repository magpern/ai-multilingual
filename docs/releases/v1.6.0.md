This is a **minor feature release** focused on administrator/operator completion for Localized URL and translation Job workflows accumulated after 1.5.1 (P0 + P1 characterization + P2). It does **not** add new Localized URL routing capability, redesign Rank Math sitemap architecture, introduce a new Job type, change schema TARGET, or require a database migration.

## Highlights

- Operators can administer Supported Localized URL candidate/publication workflows from Workspace and term screens with honest Settings admission/frontier display.
- Operators can create/monitor ordinary multi-post Jobs and understand stale/conflict outcomes without REST/CLI literacy.
- Rank Math Model A / G4 expectations are documented from characterization evidence (including DEV `blog_public=0` EXPECTED OMIT for sitemap xhtml).

## Localized URL operator improvements

From **P0 Localized URL Operator Completion**:

- Workspace localized-slug panel for post/page/product
- Term/archive localized-slug admin UI + thin `TermSlugController` REST
- Settings Localized URLs admission and frontier honesty
- `RoutePublicationService::sync_term_view` for term operator parity

**Explicit:** No new Localized URL routing capability was introduced. P0 exposes the already-Supported MSEO lifecycle to administrators.

## Jobs / stale / conflict operator improvements

From **P2 Jobs / Stale Operator Literacy**:

- Multi-post Job create without manually supplying segment keys (`bulk_translate` resolves missing segments)
- Clear Run CTA / monitoring; skipped/stale progress counts; operator status labels
- State-accurate stale copy (published vs unpublished), without absolute visitor claims
- Conflict / `skipped_conflict` literacy and next-action hints
- Capability- and state-derived recovery actions (Run remains administrator-only)
- Jobs → Operations source-level deep-link

**Preserved:** no silent overwrite; existing concurrency and stale semantics; no new Job type or Job engine.

## SEO / Rank Math characterization

From **P1 G4 / Rank Math Model A Characterization** (documentation / probe — **not** new sitemap runtime):

- Rank Math owns primary sitemap `<loc>` entries (default/source language)
- AIML may enrich qualifying Rank Math `<url>` entries with xhtml relationships when discoverability gates pass
- Advertisement is subject to existing public/discoverability gates (including WordPress `blog_public`)
- On DEV, with `blog_public=0`, xhtml omission was **EXPECTED OMIT** — this is **not** a claim that xhtml alternates are generally expected to be absent on public sites
- Verdict: **NO SUPPORTED-CONTRACT DEFECT**; no sitemap architecture redesign

## Known limitations

- Multi-post bulk Job create UI remains post-ID oriented (no picker redesign)
- Jobs → Operations navigation remains source-level (no `translation_id` enrichment; Deferred by PluginGuard)
- Optional richer multi-language UX remains backlog
- Sitemap xhtml advertisement remains subject to normal public/discoverability eligibility (including `blog_public`)
- Translated rewrite bases, Woo endpoint names, variation routes, pretty layered-nav remain Deferred/Unsupported as before

## Upgrade notes (1.5.1 → 1.6.0)

1. Install `ai-multilingual-1.6.0.zip` over the previous plugin directory (or update via your normal package path after publication).  
2. Confirm `aiml_db_version` remains **8** (`maybe_migrate()` is a no-op at TARGET 8).  
3. Existing active Localized URL routes and history remain valid.  
4. Settings and Localized URLs admission/defaults are unchanged.  
5. No special operator data migration is required.  
6. After upgrade, use Translator Workspace Jobs and Localized URL surfaces as the ordinary admin paths.

## What this release does not claim

- New Localized URL routing / SEO architecture / competing sitemaps  
- New Job execution or queue architecture  
- Schema TARGET 9 / step_9 migration  
- Public API expansion  
- Production deployment (separate authorization)
