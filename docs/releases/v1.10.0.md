# Universal Multilingual — Release Notes v1.10.0

**Status:** IN PREPARATION  
**Release version:** 1.10.0  
**Schema target:** **8** (unchanged)  
**Package (when tagged):** `universal-multilingual-1.10.0.zip`  
**Previous release:** `v1.9.0`  
**Scope audit:** [V1_10_0_RELEASE_SCOPE.md](V1_10_0_RELEASE_SCOPE.md)

This is a **minor feature release** that adds DeepSeek as a second AI translation provider and exposes per-provider generation settings (API key, model, temperature, max tokens) in Settings. It does **not** change schema TARGET, public Extension/Integration APIs, or require a database migration.

## Highlights

- Operators can select **DeepSeek** or **OpenAI** for automatic translation and AI suggestions.
- Each provider keeps its own encrypted API key, model id, temperature, and max tokens — switching providers does not wipe the other configuration.
- DeepSeek translation calls disable thinking mode so temperature and max tokens apply as configured.

## AI provider improvements

- New `DeepSeekProvider` (`https://api.deepseek.com`) implementing `AIProviderInterface`.
- Settings → Automatic translation: provider select plus OpenAI and DeepSeek fieldsets.
- OpenAI temperature is configurable (default `0.2`); optional max tokens when set above zero.
- DeepSeek defaults: temperature `1.0`, model blank → `deepseek-chat`.
- Upgrades from ≤1.9.0: existing shared API key/model migrate into the OpenAI settings slot on sanitize.

## Known limitations

- DeepSeek thinking mode / `reasoning_effort` are not operator-configurable in 1.10.0 (translation forces thinking off).
- Some OpenAI models (gpt-5*, o-series) still omit custom temperature as before.
- `max_tokens` of `0` omits the parameter (provider default).

## Upgrade notes (1.9.0 → 1.10.0)

1. Install `universal-multilingual-1.10.0.zip` over the previous plugin directory (or update via your normal package path after publication).  
2. Confirm `aiml_db_version` remains **8**.  
3. Open Settings → Automatic translation; confirm the OpenAI key/model migrated if previously configured.  
4. Optionally add a DeepSeek API key and select DeepSeek as the active provider.  
5. No special operator data migration is required.

## What this release does not claim

- Additional AI vendors beyond OpenAI and DeepSeek  
- Schema TARGET 9 / step_9 migration  
- Public API expansion  
- Production deployment (separate authorization)
