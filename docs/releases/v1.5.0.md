This release ships the **Multilingual SEO & Localized URLs (MSEO.0–MSEO.5)** program on the v1.4.0 TSC/Extension API baseline: optional administrator-controlled localized URL slugs that converge across routing, canonical, hreflang, sitemap Model A, language switcher, and ordinary outbound permalinks — without mutating WordPress/Woo source slugs and without registering AIML rewrite rules.

## What v1.5.0 adds

### Localized URL overlay (default OFF)

- Candidate localized slugs (manual/generated) distinct from active public routes  
- Active routes in `aiml_slug_routes` with source-identity history in `aiml_route_history`  
- `EffectiveUrlService` outbound authority; `Router` inbound recognition (current → history → WP)  
- Activation state machine: `off` | `activating` | `on` | `failed`  
- Hierarchical pages/terms via `HierarchyPathBuilder`  
- WooCommerce plain products and admitted `%product_cat%` product permalinks (fingerprint-gated)  
- SEO: canonical/hreflang/switcher via SB11; Rank Math sitemap xhtml:link Model A  

### Program closeout

- Program PluginGuard architecture invariants  
- Cross-milestone regression pack  
- Local/non-CI browser acceptance checklist (`acceptance/mseo-browser/`)  

## Upgrade behavior (v1.4.0 → v1.5.0)

1. Install `ai-multilingual-1.5.0.zip` over the previous plugin directory.  
2. Confirm `aiml_db_version` remains **8** (no migration in this release).  
3. Localized URLs stay **OFF** until explicitly enabled.  
4. Preview URLs remain source-slug only.  

## Known limitations (honest)

- Translated rewrite bases and Woo endpoint names are **Deferred**  
- Distinct product variation routes are **Unsupported** (parent EffectiveUrl only)  
- Pretty layered-nav is **Deferred**  
- Provider-generated slugs, rewrite ownership, competing sitemaps, fuzzy matching are **Unsupported**  
- Hierarchical ancestor-leaf localization is **Supported** (MSEO.3) — not Deferred
