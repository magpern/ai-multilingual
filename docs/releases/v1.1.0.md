## SEO

**Implemented**

- Canonical URLs and hreflang (+ `x-default`) via SB11 relationships (A.SEOb)
- Rank Math document title / meta description overlays (A.SEOc)
- Open Graph / Twitter **text** overlays on official Rank Math hooks (A.SEOd)
- Rank Math sitemap `xhtml:link` enrichment when the site is public and multilingual (A.SEOe)
- Bounded SEO diagnostics: `wp aiml seo status` and admin presentation (A.SEOf)

**Honesty / partial**

- When `blog_public=0` (Discourage search engines), public discovery enrichment is suppressed
- SC7–SC9 and some OG/Twitter surfaces remain Partially Supported per validation logs
- SF15 readiness is advisory only — **no** Search Console API automation

## Known limitations

Still current (do not treat as shipped):

1. **Translated leaf slugs** (and uniqueness / URL history / rewrite bases) remain **Deferred** (A.SEOa SA1–SA6 / SA8–SA9). Prefixed URLs continue to use source slugs (e.g. `/sv/<source-slug>/`).
2. **Deferred social image/card surfaces** (A.SEOd SD4 / SD9 / SD10 / SD12).
3. **Deferred sitemap media / reusable SitemapDiscovery contract** (A.SEOe SE10 / SE11).
4. **`blog_public=0`** honestly blocks public SEO discovery enrichment.
5. **Pre-existing `/sv/` front-page 301 self-loop** may still reproduce on some hosts (detected by diagnostics as `error/self_loop`; not fixed in A.SEOf).
6. **Pre-existing duplicate product `<title>`** (Rank Math / theme ownership) may still reproduce; AIML does not add a second title tag.
7. **No Search Console API automation** (SF15 advisory only).
8. **Diagnostics are bounded** — not a site-wide crawler.
9. Platform carry-forwards: no Elementor body translation; no nested container block identity; render cache default-off; A.6/A.7 Deferred chrome/email/body surfaces per their validation logs.
10. On some WP-CLI hosts (observed: WP-CLI 2.12 / PHP 8.4 image), `wp aiml seo status` may fail with a “RESTful WP-CLI” package error even though `wp help aiml seo` lists the command and the diagnostics service remains callable; use the admin SEO diagnostics UI or a direct service/eval invoke as a workaround.

## Upgrade from historical 1.0.0 packages

1. Install `ai-multilingual-1.1.0.zip` over the previous plugin directory (or replace via standard WP update).
2. Activate / visit wp-admin so `maybe_migrate()` runs.
3. Confirm `aiml_db_version` is **6** (unchanged target).
4. Smoke-check a published language front page, a product URL, Rank Math head output, and `wp aiml seo status`.

No destructive schema migration is introduced by 1.1.0.
