Group E — Jobs (P2)

Ordinary path: Workspace → Jobs. Creating a Job does not auto-start — administrators use Run now. Manual → Jobs.

E1

Translate missing → Run → Completed

Blocker
Preconditions AI provider available; administrator (for Run now); controlled post with missing segments.
Steps
  1. Jobs → Create job → type Translate missing.
  2. Enter post ID; Create job.
  3. Confirm status Waiting; expand; click Run now.
  4. Monitor until Completed (or Completed with skips).
  5. Verify translated result in Workspace/frontend.
Expected Job runs; progress readable; result usable. Record Job ID.
E2

Bulk translate without segment keys

Blocker
Steps
  1. Prepare 2–3 controlled posts with missing translations.
  2. Create job → Bulk translate; enter post IDs only (no segment keys).
  3. Run now; monitor; spot-check each post has missing segments filled.
Expected Bulk create succeeds without segment keys; items materialize; translations appear. (Limit awareness: ≤50 posts / ≤500 items — do not stress-test limits.)
E3

Progress / status literacy

Major
Steps During E1/E2, confirm operator labels (Waiting, Running, Completed, Completed with skips) and progress counts are understandable without REST.
Expected Vlad can explain job state from UI alone. Manual Appendix A mapping optional for notes.
E4

Run now permission (if second role available)

Major
Preconditions Existing non-admin AIML editor/translator account. If none, mark SKIP / N/A — do not invent users solely for this.
Steps
  1. As editor: create a Waiting job (if allowed).
  2. Confirm Run now absent or message that administrator must run.
  3. As administrator: Run now available.
Expected Only administrators run jobs; editors are not silently granted Run.
E5

Retry / failure path

Minor
Steps Only if a safe Failed/Retry wait job already exists. Do not break provider credentials deliberately. Otherwise SKIP.
Expected Retry failed / Resume / Run now behave as labeled without silent data loss.
E6

Expected Lands on source-level Operations context (source type/id/language). Not required to deep-link a specific translation_id.

Group G — Conflict protection

Conflict protection is intentional. Manual → Conflicts.

G1

No silent overwrite on protected target

Blocker
Preconditions Controlled content where a Job would collide with a protected/manual/reviewed translation. Typical path: manually edit/review a machine translation, then run a Job type that would overwrite (e.g. Retranslate stale / Translate selected where admitted).
Steps
  1. Protect a target translation via meaningful manual edit/review per UI.
  2. Create/run a Job that attempts overwrite.
  3. Inspect job item outcome for conflict messaging (e.g. Skipped — conflict protected).
  4. Confirm protected text still present.
  5. Follow UI recovery (Operations review/edit; confirmed retranslate only when admitted).
Expected No silent overwrite; understandable attention required; recovery does not bypass safeguards. Internal code skipped_conflict optional evidence only.
